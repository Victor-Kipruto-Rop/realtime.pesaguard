# Follow-up and Task Continuity Skill

1. Read the latest task, repository state, decisions, TODOs and CI results.
2. Classify work as complete, partial, scaffold-only, blocked or unverified.
3. Preserve approved architecture and constraints unless explicitly changed.
4. Continue from actual repository state; do not recreate files blindly.
5. Identify dependencies and the next smallest useful milestone.
6. Update code, tests, checklists and documentation together.
7. Report commits/PRs, verified tests, blockers and next steps.

A commit does not prove a feature works. Do not silently change product scope, data models or contracts. Ask only for information that materially blocks safe implementation.
